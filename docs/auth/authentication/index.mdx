NeMo Helix authenticates requests using **OpenID Connect (OIDC)**. You register an OAuth application in your identity provider, configure NeMo Helix with the issuer and client ID, and users sign in via the CLI, SDK, or browser. NeMo Helix validates the JWT on every request and extracts the user's identity for authorization.

For the quickstart (no IdP), see the [email-based shortcut](/documentation/access-control). For the authorization model, see [Authorization Concepts](/documentation/access-control/concepts).

## Log In and Make API Calls

Once your IdP is connected, see [Using Authentication](/documentation/access-control/authentication/using-authentication) for the full walkthrough: device flow login, SDK and curl examples, token management, and config file reference.

| Method | Command / Action | Best For |
|--------|-----------------|----------|
| **Device flow** (browser) | `nemo auth login` | Interactive use — opens browser to sign in with your IdP |
| **Password grant** | `nemo auth login --username <user> --password <pass>` | CI/CD pipelines — non-interactive |
| **Scoped Access Key** | `nemo auth access-keys create` | Non-SDK automation, including NeMo service accounts |
| **Direct from IdP** | Use your IdP's token endpoint or workload identity | Custom integrations that require IdP-issued scopes |

The CLI stores the token and auto-refreshes it before expiry. The SDK reads the stored token from the CLI config automatically: after `nemo auth login`, `NemoClient.from_config()` works with no arguments.

## Discovery Endpoint

NeMo Helix exposes an unauthenticated endpoint that clients and the SDK use to discover OIDC settings:

```text
GET {BASE_URL}/apis/auth/discovery
```

Response:

```json
{
  "auth_enabled": true,
  "oidc": {
    "issuer": "https://login.microsoftonline.com/{tenant}/v2.0",
    "clients": [
      {
        "name": "public",
        "client_id": "<client-id>",
        "default": true,
        "default_scopes": "platform:read platform:write openid profile email offline_access",
        "scope_prefix": "api://<client-id>/",
        "token_endpoint": "https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token",
        "device_authorization_endpoint": "https://login.microsoftonline.com/{tenant}/oauth2/v2.0/devicecode"
      }
    ]
  }
}
```

The CLI and SDK call this endpoint during `nemo auth login` and when initializing the client. `default_scopes` lists the short names users pass to the CLI. The client prepends `scope_prefix` to NeMo Helix API scopes, so `platform:read` is requested as `api://<client-id>/platform:read`.
