<a id="garak-run-audit-locally"></a>

This tutorial walks through running a single audit end-to-end with the NeMo garak plugin SDK. You will persist an audit configuration and a target, run the audit in-process, and inspect the resulting report artifacts.

**What you will learn:**

- Initialize NeMo Helix SDK and reach the `garak` resource.
- Create an `AuditConfig` selecting which garak probes to run.
- Create an `AuditTarget` pointing at a model through the Inference Gateway.
- Execute the audit locally with `garak.run(...)`.
- Read the JSONL, HTML, and hitlog report artifacts the run produces.

<Tip>

This tutorial takes approximately **10 minutes** to complete, plus however long garak takes to run the selected probes against your target.

</Tip>
## Prerequisites

- Install and start NeMo Helix using the [Setup guide](/documentation/get-started).
- Install garak in a Python virtual environment so the plugin can shell out to it. By default the plugin invokes `~/.garak/.venv/bin/python -m garak`. Override the interpreter path with `NEMO_GARAK_PYTHON` if your install lives elsewhere.
- Configure at least one Inference Gateway provider — this tutorial uses the `system/nvidia-build` provider for NVIDIA Build (`https://integrate.api.nvidia.com/v1`), with a Build API key authorized to call the selected model. Any chat-completion-compatible provider works, but its model identifiers and credentials must match that provider. Step 3 lists registered providers and checks completion access before running garak. See [Inference Gateway](/documentation/vulnerability-scanning/targets/inference-gateway) for details on the `nhx_uri_spec` block used below.

---

## Key Concepts

- **`AuditConfig`** — Selects probes, detectors, and reporting settings for a garak run. Persisted in the entity store.
- **`AuditTarget`** — Identifies the model under test (generator class, model identifier, endpoint options). Persisted in the entity store.
- **In-process run** — `garak.run(...)` shells out to garak on the host running the SDK call, writes report artifacts under a temporary directory, and returns their file paths. There is no remote job submission.

## 1. Initialize the SDK

Install the local audit interpreter (the same garak version used by the task image). This runs on the notebook host, not inside the platform containers:

```bash
python3 -m venv "$HOME/.garak/.venv"
"$HOME/.garak/.venv/bin/python" -m pip install "garak==0.17.1"
```

Connect to the running platform and reach the garak sub-resource:

```python
from nemo_garak.sdk import GarakPluginResource
from nemo_helix_plugin.client.client import NemoClient

client = NemoClient.from_config()
garak = GarakPluginResource(client)

print(garak.plugin_status())
# {'plugin': 'garak', 'status': 'ok', ...}
```

<Markdown src="/snippets/_snippets/tutorials/default-workspace-note.mdx" />

If `plugin_status()` raises a connection error, the platform is not running or your current CLI context points at the wrong deployment. Run `nemo config view` to check the context, and refer back to [Setup](/documentation/get-started) or [Connect with CLI Contexts](/documentation/reference/cli-reference/connect-to-deployments).

## 2. Create an Audit Configuration

Build a bounded configuration that runs one lightweight garak probe with one generation:

```python
from nemo_garak.entities import (
    AuditPluginsData,
    AuditReportData,
    AuditRunData,
    AuditSystemData,
)

config = garak.configs.create(
    workspace="default",
    name="quick-scan",
    description="Bounded scan using one probe and one generation.",
    system=AuditSystemData(lite=True, parallel_attempts=4),
    run=AuditRunData(generations=1),
    plugins=AuditPluginsData(probe_spec="goodside.Tag", detector_spec="auto"),
    reporting=AuditReportData(report_prefix="quick-scan"),
)
print(config.model_dump_json(indent=2))
```

For the full set of options on each sub-block, see [Configuration Schema](/documentation/vulnerability-scanning/configurations/schema). For probe selection syntax, see [Selecting Probes](/documentation/vulnerability-scanning/configurations/selecting-probes).

## 3. Create an Audit Target

First, list the providers registered in your deployment so you can pick one that exists:

```python
providers = client.models.list_providers(workspace="system")
for provider in providers.items():
    print(provider.name, provider.host_url)
```

This example uses `system/nvidia-build` with the Build model ID `nvidia/nemotron-3.5-lightning-30b-a3b`. Set `NVIDIA_MODEL` only to an exact catalog ID served by that provider's configured endpoint; it changes the model ID, not the provider route. To use a different provider from the list, change both the preflight and target routes below. Do not infer IDs by adding or removing prefixes: the endpoint, model ID, and credentials must match.

Before creating the target, send one chat completion through the same provider route that garak will use. A READY provider or a model listed in its catalog does not guarantee that your API key has completion access:

```python
import os
from nemo_helix_plugin.inference_gateway.client import InferenceGatewayClient
from nemo_helix_plugin.inference_gateway.types import JsonBody

MODEL_ID = os.environ.get("NVIDIA_MODEL", "nvidia/nemotron-3.5-lightning-30b-a3b")

completion = InferenceGatewayClient.from_client(client).provider_post(
    workspace="system",
    name="nvidia-build",
    trailing_uri="v1/chat/completions",
    body=JsonBody({
        "model": MODEL_ID,
        "messages": [{"role": "user", "content": "Reply with hello."}],
        "max_tokens": 1024,
    }),
).data()
content = completion["choices"][0]["message"].get("content")
if not content:
    raise RuntimeError("Completion returned no content; inspect the response before auditing.")
print(content)
```

If this request fails, resolve the provider/model or credential issue before starting the audit; see Troubleshooting below.

Define the model under test. This example uses garak's `nim.NVOpenAIChat` generator pointed at the `system/nvidia-build` provider:

```python
target = garak.targets.create(
    workspace="default",
    name="nemotron-3.5-lightning-30b",
    type="nim.NVOpenAIChat",
    model=MODEL_ID,
    options={
        "nim": {
            "max_tokens": 1024,
            "nhx_uri_spec": {
                "inference_gateway": {
                    "workspace": "system",
                    "provider": "nvidia-build",
                },
            },
        },
    },
)
print(target.model_dump_json(indent=2))
```

The `nhx_uri_spec` sentinel inside `options.nim` tells the plugin to resolve a concrete URI from the Inference Gateway provider at run time. See [Inference Gateway](/documentation/vulnerability-scanning/targets/inference-gateway) for the full conflict rules and resolution behavior.

## 4. Run the Audit Locally

`run()` accepts either inline entities or name strings that reference entities in the entity store. Pass the names you persisted above:

```python
result = garak.run(
    config="quick-scan",
    target="nemotron-3.5-lightning-30b",
    workspace="default",
)

print(f"Audit status: {result['status']}")
if result["status"] == "failed":
    print(f"Audit failed: {result.get('error', 'unknown error')}")
else:
    print(result["probes_complete"], result["probes_failed"])
    # 1 0
    for name, ref in result["results"].items():
        print(f"{name}: {ref['artifact_url']}")
    # report-jsonl: file:///var/folders/.../results/report-jsonl
    # report-html: file:///var/folders/.../results/report-html
    # report-hitlog-jsonl: file:///var/folders/.../results/report-hitlog-jsonl
```

If you prefer to skip the entity-store roundtrip, pass the inline `AuditConfig` and `AuditTarget` objects from the previous two steps directly:

```python
result = garak.run(config=config, target=target, workspace="default")
```

## 5. Read the Results

`run()` returns `file://` URLs for whichever of the three report types garak produced. Parse them with `urllib.parse.urlparse` to recover local paths, then load them as needed.

Load the JSONL probe-by-probe summary:

```python
import json
from pathlib import Path
from urllib.parse import urlparse

def url_to_path(url: str) -> Path:
    return Path(urlparse(url).path)

jsonl_path = url_to_path(result["results"]["report-jsonl"]["artifact_url"])
records = [json.loads(line) for line in jsonl_path.read_text().splitlines() if line.strip()]
print(f"Loaded {len(records)} report entries.")
```

Summarize hits per probe from the hitlog:

```python
from collections import Counter

hitlog_ref = result["results"].get("report-hitlog-jsonl")
if hitlog_ref is None:
    print("No hits recorded — every probe passed.")
else:
    hitlog_path = url_to_path(hitlog_ref["artifact_url"])
    hits = [json.loads(line) for line in hitlog_path.read_text().splitlines() if line.strip()]
    by_probe = Counter(entry.get("probe") for entry in hits)
    for probe, count in by_probe.most_common():
        print(f"{probe}: {count} hits")
```

The HTML report at `result["results"]["report-html"]["artifact_url"]` is the most human-friendly summary — open it in a browser to see grouped pass/fail counts and per-probe details.

## 6. Clean Up

Delete the entities you created:

```python
garak.configs.delete(workspace="default", name="quick-scan")
garak.targets.delete(workspace="default", name="nemotron-3.5-lightning-30b")
```

Report artifacts are left in place under the scheduler's temporary directory; the OS reaps them eventually.

## Troubleshooting

**`FileNotFoundError: garak interpreter not found at ...`**
: The plugin couldn't find a garak install. Either install garak at `~/.garak/.venv/bin/python`, or set `NEMO_GARAK_PYTHON` to the absolute path of a Python interpreter that has garak installed.

**`RuntimeError: Failed to resolve inference gateway provider '<workspace>/<provider>'`**
: The `nhx_uri_spec` block in your target's options references an Inference Gateway provider that doesn't exist. List providers in the workspace named by that reference: this tutorial uses `client.models.list_providers(workspace="system")` for `system/nvidia-build`. Update the reference to an existing provider in that workspace. The audit target remains in `default`; its workspace is separate from the provider's workspace.

**HTTP 403, 404, or 424 during the completion preflight**
: Check the provider, its API base URL, the exact model ID in its served-model catalog, and the provider's configured API key. An upstream 403 (`Authorization failed` or `key_model_access_denied`) indicates an authorization/access failure; confirm both the model ID and the key's access with that provider. An upstream 404 can indicate an incorrect model ID, such as a duplicated `nvidia/` prefix on NVIDIA Build. The platform may wrap an upstream failure as HTTP 424; inspect the response body for the upstream status and error. Do not retry the audit until the completion preflight succeeds.

**HTTP 504 during the completion preflight**
: The upstream completion timed out. Provider readiness and model discovery are not successful completion tests. Retry the preflight or choose another model available to your provider and credential before running garak.

**`status == "failed"` with empty `results`**
: The audit could not complete any probe. Inspect `result.get("error")` for the failure reason, and verify the model is reachable through the provider you configured.

**Where do the report files live?**
: The scheduler writes garak output under `<temp-dir>/garak/<reporting.report_dir>/<reporting.report_prefix>.*`, then copies the produced files into the local results directory referenced by each `artifact_url`. For a local run this is a temporary directory under the system's `$TMPDIR`.
