title: "Sandboxed Deployments"
description: "Package a Fabric agent for OpenShell, deploy it, and verify inference and network policy."
---

Deploy a registered Fabric agent with `--mode openshell` to run it under the
OpenShell executor's policy. This mode is independent of the gateway's Docker or
Kubernetes compute driver. Requests still go through the platform's Agents gateway.

## Before you start

- Connect the CLI to your platform using its saved context.
- Configure an OpenShell deployment executor using the
  [OpenShell operator guide](/documentation/kubernetes-deployment/setup/helm/openshell).
- Prepare a working Fabric `agent.yaml`, with a model available through the
  platform's Inference Gateway. See [Agents](/documentation/agents).
- Choose an image registry reachable by the gateway's compute nodes. Configure
  private-registry credentials on OpenShell when needed.

Use the same workspace for registration, deployment, invocation, and cleanup:

```sh
export WORKSPACE=default
export AGENT_NAME=sandbox-hello
export AGENT_CONFIG="agents/$AGENT_NAME/agent.yaml"
export IMAGE_TAG="registry.example.com/team/$AGENT_NAME:0.1"
```

Replace the registry with yours and confirm the model works before diagnosing
sandbox connectivity. Keep secrets out of the agent config and image build context.

## Package and publish

Build with the OpenShell runtime profile so the image includes the required
user and operating-system dependencies:

```sh
nemo agents package --agent "$AGENT_CONFIG" \
  --sandbox-runtime openshell --tag "$IMAGE_TAG"
docker push "$IMAGE_TAG"
```

For an agent with local Python code, include its `--pyproject` file as described
in [Deploy Agents](/documentation/agents/deploy-agents). Match the image architecture
to the gateway's compute nodes. A local image must be loaded into those nodes or
published; building it on the CLI host alone does not make it available remotely.

For a source checkout, run these commands from the repository root with that
checkout's CLI on `PATH`:

```sh
uv build --package nemo-helix --wheel --out-dir dist
NEMO_AGENTS_WHEEL=LATEST nemo agents package --agent "$AGENT_CONFIG" \
  --sandbox-runtime openshell --tag "$IMAGE_TAG"
```

Do not bypass package validation.
Rebuild older agent images after platform schema changes. An image built against
an older agent schema can reject the configuration delivered by a newer platform
before its server becomes ready, even when sandbox creation succeeds.

## Register and deploy

```sh
nemo agents create --name "$AGENT_NAME" \
  --agent-config "$AGENT_CONFIG" --workspace "$WORKSPACE"

nemo agents deploy --agent "$AGENT_NAME" \
  --name "$AGENT_NAME-sandbox" --mode openshell \
  --image "$IMAGE_TAG" --workspace "$WORKSPACE" --timeout 600
```

The operator's `agents.deployments.openshell_executor` selects the OpenShell
backend. Do not point `k8s_executor` at OpenShell or use `--mode k8s` for this
deployment. Wait for the deployment to reach `running`; a created sandbox alone
does not prove the agent is ready.

## Invoke and verify policy

```sh
nemo agents invoke --agent-deployment "$AGENT_NAME-sandbox" \
  --workspace "$WORKSPACE" --input "Reply with a short greeting."
```

Confirm the response contains usable model output. If invocation fails after
the deployment becomes ready, inspect the agent log and the platform's route to
the gateway. Readiness alone does not prove model access or end-to-end proxying.

With the OpenShell CLI connected to the same gateway and gateway workspace,
select the sandbox belonging to this deployment. Check both deployment-name and
deployment-workspace labels; do not pick another workload by name prefix.

```sh
openshell sandbox list
```

Set `SANDBOX_NAME` to that sandbox and `PLATFORM_API_URL` to the HTTP endpoint
configured by the operator's `platform_egress`. Then run:

```sh
openshell sandbox exec --name "$SANDBOX_NAME" -- \
  curl --fail --show-error --max-time 10 "$PLATFORM_API_URL/health/ready"
openshell sandbox exec --name "$SANDBOX_NAME" -- \
  curl --fail --show-error --max-time 10 https://example.com
```

For the default generated policy, the platform health request should succeed
and the external request should be denied. Confirm a policy denial in the
gateway output/logs; a timeout or DNS failure alone does not prove enforcement.
If a custom policy allows external hosts, choose a destination outside its allowlist.
Invoke the agent again to confirm model access still works.

## Clean up

```sh
nemo agents undeploy "$AGENT_NAME-sandbox" --workspace "$WORKSPACE" --yes
nemo agents delete "$AGENT_NAME" --workspace "$WORKSPACE" --yes
```

Verify the sandbox is gone from the gateway. The published image is retained in
your registry. See the operator guide for gateway authentication, image-pull,
working-directory, and policy troubleshooting.
