<a id="agents-insights-analysis"></a>

NeMo Compass reads an agent's traces from NeMo Intake, looks for problems that
recur across them, and files each one as an **Insight**: a named, persistent
description of a recurring problem, backed by the traces that show it. Review
Insights in [NeMo Studio Insights](/documentation/studio/insights), then
resolve them as you fix the agent.

Compass is itself an agent in your workspace: a
[plugin-managed agent](/documentation/agents/plugin-managed-agents) of type
`compass.analyst`, named `compass-analyst`. Each analysis is an
[execute job](/documentation/agents/execute-agents-as-jobs) of that agent,
whose context names the agent to analyze. Submit one on demand, or opt an agent
in to periodic analysis and let the platform submit them on a daily or weekly
schedule.

## Before You Start

You need:

- A running NeMo Helix with the Compass plugin and Intake. The plugin is
  installed by default. Analyses run as execute jobs, so the platform also
  needs a working `agents.execute` runtime.
- Traces for the agent in Intake. Compass can only diagnose what it can
  observe. See [Collect Agent Traces](/documentation/agents/traces-and-insights/collect-agent-traces).
- A default and fast model pair. `nemo setup` stores one, and the CLI fills it
  in on each run; you can also name the models in the run's context.
- The workspace's Compass agent. See [Create the Compass Agent](#create-the-compass-agent) below.

<Warning>

NVIDIA Nemotron 3.5 Lightning 30B (`nvidia/nemotron-3.5-lightning-30b`) has known
tool-calling failures in Compass. Use **NVIDIA Nemotron 3.5 Super VL** instead
for both the default and fast models.

</Warning>

<Note>

For PyPI installations, `nemo-helix[all]` includes Compass on
Python 3.12 and 3.13.

</Note>

### Telemetry Requirement

The analysis selects traces by agent name, so the normalized `agent_name` on
the agent's traces must match the `agent` you name in the run's context. For
OTLP, set `gen_ai.agent.name` on every span; Intake also normalizes
`llm.agent.name` and `agent.name`. ATIF trajectories map their required
`agent.name` automatically.

## Create the Compass Agent

A workspace has at most one Compass agent, used to analyze any agent traces in the
workspace. Create it once:

```bash
nemo agents create compass.analyst
```

It is named `compass-analyst`; pass `--name` to choose another name. Its config
comes from the installed Compass plugin whenever it runs, so there is nothing to
configure, and it picks up plugin upgrades without being created again.
Creating it requires permission to create agents in the workspace.

`nemo compass analysis enable` also creates it when the workspace has none. See
[Run Analysis on a Schedule](#run-analysis-on-a-schedule).

## Give the Agent an Ethos

An **Ethos** is a Markdown document that describes an agent's intended
behavior, constraints, and success criteria: context that its traces don't
contain. With one, Compass's `ethos-divergence` Signal looks for behavior that
departs from it. Without one, Compass can only judge the agent against itself.

Compass reads the Ethos from `ETHOS.md` in the analyzed agent's Ethos fileset,
`<agent>-ethos`, in the workspace the analysis runs in. Every analysis reads
it, on demand or scheduled, when its job is submitted.

When you register an agent from a directory with `nemo agents register`, the
directory's text files are uploaded to that fileset, so an `ETHOS.md` beside
`agent.yaml` is picked up. Otherwise, such as for an agent known only from its
traces, upload it yourself. `--exist-ok` keeps an existing fileset:

```bash
nemo files filesets create my-agent-ethos --exist-ok
nemo files upload ETHOS.md my-agent-ethos
```

An agent with no `ETHOS.md`, or a blank one, is analyzed without an Ethos, and
`ethos-divergence` is skipped. If you are not allowed to read the fileset, the
run is rejected when you submit it, rather than analyzing the agent without
the Ethos you expected it to apply.

## How an Analysis Works

1. **Load traces.** The run reads the agent's traces and their spans from
   Intake. The optional `since` and `evaluation_id` context keys narrow which traces
   are read.
1. **Collect evidence.** Several Compass Signals (evidence streams) examine the
   traces in parallel. Each stream either reports the problems it found or is
   skipped with a reason.
1. **Apply recurrence thresholds.** Isolated failures are dropped. Only
   observations that recur often enough become Insight candidates. See
   [Recurrence Thresholds](#recurrence-thresholds).
1. **Compile Insights.** The default model turns candidates into Insights and
   compares them with the agent's existing unresolved Insights. A new problem
   becomes a new Insight; more evidence for an existing problem is appended to
   that Insight's evidence. Compass does not change the title, description, or
   status of an existing Insight.
1. **Save the report.** The job's `compass.save-insights` post-run action files
   the Insights and saves an `analysis-report` result that records what the run
   created, updated, and left out.

### Compass Signals

| Stream | Looks for | Skipped when |
| ------ | --------- | ------------ |
| `tool-issues` | Problems in tool calls, such as explicit tool failures, grouped by tool and issue type. | The traces contain no tool calls. |
| `anomaly-and-patterns` | Statistical outliers, clusters of similar trajectories, and failures that recur with the same signature. | — |
| `grader-failure-patterns` | Patterns among traces linked to failed evaluation results. | The traces have no evaluator results. |
| `ethos-divergence` | Behavior that diverges from the agent's intended behavior, as described in its [Ethos](#give-the-agent-an-ethos). | The agent has no Ethos. |
| `user-sentiment` | User complaints in recorded user messages. | No embedding backend is configured. Compass runs do not configure one, so this stream is always skipped. |

Every stream is skipped with `No traces loaded` when the run finds no traces.

### Recurrence Thresholds

Compass only files an Insight for a problem that recurs:

| Stream | Threshold | What is counted |
| ------ | --------- | --------------- |
| `tool-issues` | 3 | Independent cases |
| `anomaly-and-patterns` | 3 | Distinct traces |

An **independent case** is the evaluation test case name of the trace or, when
the trace has none, the trace ID. Traces from the same evaluation test case
count as one case, even when they come from separate sessions or repeated
attempts. For example, three failing traces for one test case count as 1 of 3,
and that tool issue is not filed.

The thresholds are fixed; you cannot configure them. A run scoped with `since`
or `evaluation_id`, or a run over a low-traffic agent, can see a real problem
that does not yet meet them. The report lists these near misses so you can tell
"nothing is wrong" apart from "not enough evidence yet". See
[Read the Analysis Report](#read-the-analysis-report).

## Run an Analysis On Demand

Submit an execute job of the Compass agent, naming the agent to analyze in its
context:

```bash
nemo agents execute --agent compass-analyst \
  --spec '{"context": {"agent": "my-agent"}}'
```

The CLI fills in `default_model` and `fast_model` from `nemo setup` when the
context leaves them out, and says so on stderr. The command prints the created
job. Watch it by its `name`:

```bash
nemo jobs watch <job-name>
```

`nemo jobs watch` streams the job's logs and exits non-zero unless the job completes.

The context takes these keys:

| Key | Effect |
| --- | ------ |
| `agent` | Required. The agent to analyze, by the name its traces carry. It does not need to be a registered Helix agent entity. |
| `default_model` | Required. The default model, as a Model Entity name or a `<workspace>/<name>` ref; a bare name resolves in the job's workspace. The CLI fills it in from `nemo setup`. |
| `fast_model` | A second, typically faster model Compass uses for part of its analysis, in the same form. The CLI fills in the configured fast model; a run without one uses `default_model`. |
| `since` | Analyze only traces that started at or after this ISO-8601 timestamp, such as `2026-10-01T00:00:00+00:00`. |
| `evaluation_id` | Analyze only traces from one Evaluation. |

The context is checked when you submit the run. An unknown key, or a model that
does not exist or uses an unsupported backend, is rejected before the job is
created.

To analyze one candidate of an agent, set `evaluation_id` to its Evaluation
name rather than bounding the run with `since`. Refer to
[Evaluate Agent Candidates](/documentation/agents/traces-and-insights/evaluate-agent-candidates).

An on-demand run does not have a minimum trace count. A run that finds no traces
still completes, files nothing, and reports `Analyzed 0 traces`.

### List Analyses

Each Compass job records the agent it analyzed as its `spec.subject`. To list one
agent's analyses, on demand and scheduled, newest first:

```bash
nemo agents list-jobs --agent compass-analyst --filter '{"spec.subject": "my-agent"}'
```

Drop `--filter` to list every analysis in the workspace.

## Read the Analysis Report

The `analysis-report` result is the record of what one run did. Insights do not
record which run created them. Download it like any other
[job result](/documentation/agents/execute-agents-as-jobs#track-a-job-and-fetch-its-results):

```bash
nemo jobs results download analysis-report --job <job-name> -o analysis-report.txt
cat analysis-report.txt
```

A report has a summary line, then one line per Insight created or updated, then
notes about what the run left out:

```text
Analyzed 6 traces: 0 new insights, 0 existing insights with new evidence. Some observations did not meet minimum recurrence thresholds and were not promoted to insight candidates; see the analysis report for details.

- no insights created or updated
- below threshold: tool-issues knowledge_search explicit_tool_failure (2 of 3 independent cases)
- skipped: ethos-divergence (No ethos document)
- skipped: grader-failure-patterns (No evaluator results)
- skipped: user-sentiment (No embedding backend configured)
```

| Line | Meaning |
| ---- | ------- |
| `- created: <title> [<id>] (<n> trace refs)` | The run filed a new Insight. |
| `- updated: <id> (<n> trace refs)` | The run added new trace evidence to an existing Insight. |
| `- no insights created or updated` | The run filed nothing. |
| `- below threshold: tool-issues <tools> <issue type> (<count> of 3 independent cases)` | A tool issue recurred, but in too few independent cases. |
| `- below threshold: anomaly-and-patterns <signature> (<count> of 3 traces)` | A failure pattern recurred, but in too few traces. |
| `- ... and <n> more below threshold` | More near misses exist. The report lists the 5 closest to the threshold. |
| `- skipped: <stream> (<reason>)` | An evidence stream did not run. The reason says why. |

The summary line appears both in the report and in the job's Fabric run
result. When any observation falls below a threshold, the summary ends with the
sentence about minimum recurrence thresholds.

When the report shows a `below threshold` line, you can:

- Widen the run: drop `since` or move it back, or drop `evaluation_id`.
- Wait for more traffic and run again. For an evaluation, add test cases that
  exercise the failing tool; repeating the same test case does not add
  independent cases.
- Supply the missing input for a skipped stream, such as an
  [Ethos](#give-the-agent-an-ethos) or evaluator results.

## Run Analysis on a Schedule

Opt an agent in to periodic analysis:

```bash
nemo compass analysis enable --agent my-agent
nemo compass analysis status                    # all agents in the workspace
nemo compass analysis status --agent my-agent
nemo compass analysis disable --agent my-agent
```

`enable` stores the model pair that scheduled runs use: the `nemo setup` pair,
or the pair from `--default-model` and `--fast-model`. Scheduled runs do not read
your CLI configuration, so run `enable` again after you change the pair.

`enable` also creates the workspace's Compass agent when it has none. If you
cannot create agents, the agent is still opted in, but its scheduled runs do
not start until someone
[creates the Compass agent](#create-the-compass-agent).

Scheduled runs are ordinary Compass jobs: they read the agent's Ethos and show
up in [its list of analyses](#list-analyses) like on-demand runs.

A controller checks each opted-in agent every 60 seconds and submits a run when
all of the following are true:

- The scheduled time has passed since the agent's last successful run.
- No Compass job is already active for the agent, whether scheduled or on demand.
- At least 10 new sessions have arrived since the last successful run. The
  first scheduled run for an agent skips this check.

Scheduled runs are incremental: each analyzes traces starting from the previous
successful run’s start time. Late-arriving traces with an earlier start time may be missed.
On-demand runs do not affect the schedule.

`status` shows whether each agent is enabled and which model pair it uses. The
scheduler's own state for an agent, including the last error, is available from Python:

```python
from nemo_helix_plugin.client.client import NemoClient
from nemo_compass_plugin.sdk import CompassPluginResource

client = NemoClient.from_config()
compass_client = CompassPluginResource(client)
state = compass_client.analysis_run_statuses.get(workspace="default", agent="my-agent")
print(state.status, state.last_successful_run_at, state.last_error)
```

`status` is `idle`, `running`, or `error`. The state is `error` when a scheduled
run cannot start or does not succeed, and `last_error` says why:

| `last_error` | Meaning |
| ------------ | ------- |
| `Workspace '<workspace>' has no Compass agent; ...` | [Create the Compass agent](#create-the-compass-agent). |
| `Analysis job was rejected: <detail>` | The run was rejected when it was submitted, for example because a stored model no longer exists. Run `enable` again with a working model pair. |
| `Analysis job <status>`, such as `Analysis job error` | The scheduled job ran and did not complete. The state's `last_submitted_job` names it; check its logs with `nemo jobs tail <job-name>`. |

### Configure the Schedule

The schedule is a deployment setting that applies to every opted-in agent. Set
it in the `compass:` section of the platform configuration file:

```yaml
compass:
  analysis:
    enabled: true            # run the periodic analysis controller
    frequency: daily         # daily or weekly
    run_at_hour: 0           # local hour of day, 0-23
    run_on_weekday: monday   # used only when frequency is weekly
    timezone: UTC            # IANA name, such as America/Denver
    job_profile: default     # jobs execution profile for scheduled runs
```

| Setting | Default | Description |
| ------- | ------- | ----------- |
| `enabled` | `true` | Whether the periodic analysis controller runs. |
| `frequency` | `daily` | `daily` or `weekly`. |
| `run_at_hour` | `0` | Hour of day that runs become due, in `timezone`. |
| `run_on_weekday` | `monday` | Day of week runs become due. Used only with `weekly`. |
| `timezone` | `UTC` | IANA time zone name. Runs keep their local hour across daylight saving changes. An unknown name fails validation. |
| `job_profile` | `default` | Jobs execution profile for scheduled Compass jobs. |

## Review Insights

Open **Observability > Insights** in NeMo Studio to review, resolve, delete, or
reopen Insights. See [NeMo Studio Insights](/documentation/studio/insights).

To list Insights from Python:

```python
from nemo_helix_plugin.client.client import NemoClient
from nemo_compass_plugin.sdk import CompassPluginResource

client = NemoClient.from_config()
compass_client = CompassPluginResource(client)
page = compass_client.insights.list_insights(workspace="default", agent="my-agent", status="open")
for insight in page.data:
    print(f"[{insight.status}] {insight.title} ({len(insight.evidence)} traces)")
```

Each Insight has a `title`, a `description`, the `agent` it is about, a
`status` (`open`, `resolved`, or `deleted`), and `evidence`: traces cited to
support the finding, optionally with specific spans:

```yaml
evidence:
  - trace_id: trace-a
    spans:
      - span_id: span-123
  - trace_id: trace-b
```

Each trace or span may also have an optional `url` supplied by the trace provider.
Without spans, an entry refers to the whole trace. Existing stored Insights using
`trace_refs`/`trace_links` and `span_refs`/`span_links` are read as this structured
format automatically; no data migration is required.

Insights can also include `severity` and `confidence` (`low`, `med`, or `high`)
and `updated_date`, the timestamp supplied by Compass. These fields are optional.
When a later run adds evidence, Helix merges it by trace and span ID and updates
`updated_date`, while preserving the existing Insight's identity, title,
description, status, severity, and confidence. Resolved Insights are excluded
from reconciliation, so a resolved problem that comes back can be filed as a
new Insight.

## Troubleshooting

### The Run Is Rejected When You Submit It

- **The Compass agent does not exist.** `nemo agents execute` fails because the
  workspace has no `compass-analyst`. [Create it](#create-the-compass-agent).
- **The context has no `default_model`.** The CLI had no model pair to fill in.
  Run `nemo setup`, or set `default_model` (and optionally `fast_model`) in the
  context.
- **A model is unknown or unsupported.** Use a Model Entity that exists and that
  Compass can call. A bare name resolves in the job's workspace.
- **Permission denied.** Submitting needs permission to run the Compass agent,
  and to read the analyzed agent's Ethos fileset when it has one.

### The Run Completes but Files No Insights

Download the `analysis-report` result and check it:

- `Analyzed 0 traces`: no traces matched. Check that the context's `agent`
  matches the agent name on the traces (see
  [Telemetry Requirement](#telemetry-requirement)), that the workspace is
  correct, and that `since` and `evaluation_id` are not too narrow.
- `below threshold` lines: the problem is real but has not recurred enough.
  See [Read the Analysis Report](#read-the-analysis-report).
- Only `skipped` lines: no stream that ran found a problem.

### Periodic Analysis Does Not Start

- Check that the agent is enabled with `nemo compass analysis status`.
- Check the scheduler's `last_error` for the agent. See
  [Run Analysis on a Schedule](#run-analysis-on-a-schedule).
- Check that `compass.analysis.enabled` is true.
- Check that the scheduled time has passed in the configured `timezone`.
- After the first scheduled run, a run starts only when at least 10 new sessions
  have arrived since the last successful run.
- If status shows no model pair, run `nemo compass analysis enable` again
  with a model pair.
