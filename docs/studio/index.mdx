<Note>

Studio is still in early development. Many features are missing or should be expected to change.

</Note>

NeMo Studio is the web app for AI development with NVIDIA NeMo Helix. It provides a workspace-oriented UI for managing local platform resources, reviewing agents, running agent optimization workflows, monitoring agent telemetry, and working with filesets, jobs, and secrets.

The pages visible in your workspace depend on the installed plugins, enabled services, feature flags, and NeMo Helix version. A page documented here might be hidden in your deployment. Preview pages identify the feature flag that enables them.

---

## Getting Started

NeMo Studio is included with the platform. Follow the [Setup guide](/documentation/get-started) to start NeMo Helix, then access Studio at `/studio` on your running server.

When you sign in through the direct OIDC flow, Studio attempts to create a workspace using your email prefix; see [Workspace creation on login](/documentation/get-started/core-concepts/workspaces#workspace-creation-on-login).

## Features

### Current Workspace Navigation

The sidebar is a flat list of pages under task-named section headings. Select a heading to collapse or expand its section; Studio remembers your choice in this browser.

| Sidebar section      | Entry                  | Purpose and availability |
| -------------------- | ---------------------- | ------------------------ |
| _(no heading)_       | **Dashboard**          | Workspace summary, quickstart shortcuts, and recent jobs. Shown by default; see [Dashboard](#dashboard). |
| _(no heading)_       | **Playground**         | Opens the model chat playground. Always shown. |
| **Agent Development** | **Agents**            | Opens the agent list. Select an agent to access the Overview, Deployments, Logs, Chat, Evaluations, Optimizations, Insights, and Details tabs. Optimizations and Insights are enabled by default and can be hidden by their feature flags. |
| **Agent Development** | **Monitor**           | Review inference runs and token usage across agents. Disabled by default; shown when `VITE_FF_MONITOR_ENABLED` is enabled. |
| **Agent Development** | **Experiments**       | Group evaluations for comparison, drill into results, and compare runs side by side; see [NeMo Studio Experiments](/documentation/studio/experiments). |
| **Agent Development** | **Tasksets**          | Browse the read-only taskset library used by evaluations. Disabled by default; shown when `VITE_FF_TASKSETS_ENABLED` is enabled (and evaluations are enabled). |
| **Agent Development** | **Tasks**             | Browse evaluation tasks and see which tasksets use them. Shown alongside **Tasksets**. |
| **Agent Development** | **Insights**          | Review optimization insights generated from observed agent sessions. Shown when optimization is enabled; see [NeMo Studio Insights](/documentation/studio/insights). |
| **Agent Development** | **Traces**            | Inspect ingested traces, spans, and session details; see [NeMo Studio Traces](/documentation/studio/traces). |
| **Models**           | **Model Catalog**      | Opens the base-model list; see [Models](#models). |
| **Models**           | **Model Evaluations**  | Opens the Model Evaluations page; see [NeMo Studio Model Evaluations](/documentation/studio/model-evaluations). |
| **Models**           | **Fine-tuning**        | Opens the fine-tuned models list. Enabled by default; see [NeMo Studio Fine-tuning](/documentation/studio/customization). |
| **Models**           | **Deployments**        | Lists model deployments. Shown when that capability is enabled. |
| **Models**           | **Virtual Models**     | Inspect Inference Gateway routes. Shown by default; hidden only when both the Guardrails preview feature and agent optimizations are disabled. |
| **Resources**        | **Datasets**           | Browse and create dataset-purpose filesets; see [Datasets](#datasets). |
| **Safety**           | **Guardrails**         | Manage guardrail configurations. Disabled by default; see [Studio Guardrail Configs](/documentation/studio/guardrail-configs). |
| **Safety**           | **Agent Hardening**    | Plugin-provided agent hardening UI. Appears only when the Agent hardening plugin is installed; see [Studio Plugin UIs](/documentation/studio/plugins). |
| **Data Preparation** | **Data Designer**      | Build and monitor synthetic-data jobs; see [Data Designer in NeMo Studio](/documentation/studio/data-designer). |
| **Data Preparation** | **Safe Synthesizer**   | Create and monitor privacy-preserving synthetic tabular data jobs. Enabled by default. |
| **Data Preparation** | **Anonymizer**         | Detect and protect PII in a dataset. Enabled by default; see [NeMo Studio Anonymizer](/documentation/studio/anonymizer). |
| **Workspace**        | **Inference Providers** | Manage the inference providers registered in the workspace. |
| **Workspace**        | **Filesets**           | Organize and manage files used by agents and jobs. |
| **Workspace**        | **Jobs**               | Monitor jobs across enabled platform capabilities. |
| **Workspace**        | **Settings**           | View workspace settings and open **Secrets** and inference provider management. Enabled by default. |

**Insights** and **Traces** currently live under **Agent Development**. Flag-gated entries are hidden when their capability is disabled. Plugins contribute navigation at runtime: an installed plugin's pages join an existing section when it names that section, or appear in a new section.

### Dashboard

The workspace **Dashboard** is the first entry in the sidebar and the page a workspace opens on. It shows workspace summary tiles, a **Quickstart** section, and a **Recent Jobs** list.

The Dashboard is shown by default and controlled by `studio.feature_flags.dashboard_sandbox_enabled` (default `true`). When an administrator sets it to `false`, and `studio.feature_flags.assistant_studio_enabled` is also off, Studio hides the Dashboard entry and route, and workspaces open on the **Agents** list instead.

#### Quickstart

**Quickstart** groups shortcuts into panels. A panel or shortcut appears only when its capability is enabled. In the **Connect an Agent** panel:

- **Upload an Agent** opens **Register an agent with NeMo Helix** on the code-upload tab.
- **Import from GitHub** opens the same dialog on the **Register from GitHub** tab. See [Register an Agent](/documentation/studio/agents#register-an-agent).

You can dismiss the Quickstart section. In a sample sandbox workspace, a sample-workload panel replaces the Quickstart shortcuts.

#### Recent Jobs

**Recent Jobs** lists jobs in progress and jobs that reached a terminal state in the last 48 hours. It appears whenever the Dashboard does and has no separate setting to hide it. The list shows newest jobs first, ten rows per page with pagination, in these columns:

| Column           | Shows                                                                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Name**         | The job's name.                                                                                                                                                      |
| **Source**       | A badge for the service that created the job.                                                                                                                        |
| **Status**       | A status badge; see the statuses under [Jobs](#jobs).                                                                                                                |
| **Elapsed time** | Time since the job was created, including while it's pending. The value counts up live while the job is active, and stops at the job's last update once it finishes. |

The list refreshes automatically, so there's no refresh button. Selecting a row opens the job's service-specific detail page, or the generic job detail view when that service isn't enabled. When no jobs match, the empty state offers a **Fine-tune** call to action if fine-tuning is enabled (`studio.feature_flags.customizer_enabled`).

### Agents

Use the Studio Agents area to review NeMo Helix-managed agents, including the current Fabric-first `nemo-agents-spec-v1` experience, inspect agent details, deploy agents, open a chat session against a running deployment, and clean up deployments that are no longer needed.

For the full workflow, see [Studio Agents](/documentation/studio/agents).

### Insights

Use **Agent Development > Insights** to review optimization insights Compass generates from observed agent sessions and traces, and drill into an insight's linked experiments and observed sessions. Use **Resolve** or **Delete** to close an open insight, and **Reopen** to restore a resolved or deleted one.

For the full workflow, see [Studio Insights](/documentation/studio/insights).

### Traces

Use **Agent Development > Traces** to inspect ingested telemetry in the Traces and Spans tables, and drill into a session's trace and span detail, with specialized views for LLM, tool, agent, chain, embedding, reranker, retriever, guardrail, and evaluator spans.

For the full workflow, see [Studio Traces](/documentation/studio/traces).

### Guardrails

When the preview feature is enabled, use **Safety > Guardrails** to create and manage NeMo Guardrails configurations for the current workspace. Select **Create Guardrail** to add a configuration. The list shows each config's **Name**, **Main Model**, **Flows**, and **Updated** columns, with an optional **Created** column; use the row actions to **Duplicate** or **Delete** a config, or select several rows to delete them together.

Select a row to open the detail page, which has **Configuration**, **Test and Validate**, and **Virtual Models** tabs. The **Configuration** tab lets you edit the main model and rails, and shows the full payload as read-only **Configuration JSON**. Select **Save Guardrail** to apply your changes or **Reset** to discard them. The detail page also offers **Duplicate** and **Delete** actions.

For the full workflow, see [Studio Guardrail Configs](/documentation/studio/guardrail-configs).

### Virtual Models

Use **Models > Virtual Models** to inspect inference routes managed by the Inference Gateway. The list shows all user-created virtual models in the workspace — auto-provisioned passthrough routes are hidden. Select a row, or choose **View** from its row actions, to open the virtual model's detail page. The **Details** tab shows the default backend model when configured, and the ordered request, response, and post-response middleware pipelines attached to the route. The **Chat** tab sends test prompts through the virtual model. Row actions also include **Chat** and **Delete**.

Virtual models are created through the `nemo inference virtual-models` CLI or the Inference Gateway API.

For the full workflow, see [Studio Virtual Models](/documentation/studio/virtual-models).

### Models

Select **Models > Model Catalog** to browse base-model entities available in the current workspace. **Model Catalog** is the base-model list. Base models include models registered in the workspace and default platform models.

The Model Catalog page supports searching by model name, filtering by creation or update date, sorting alphabetically or by creation time, and showing only customizable models. Select a model card to open the model details side panel.

The model details side panel has **Model Details** and **Chat Playground** tabs. **Model Details** shows model metadata, parameters, and available actions, such as **Customize this Model** when fine-tuning is enabled. **Chat Playground** lets you chat with chat-capable models.

In the chat, a model's streamed reasoning appears live in a collapsible **Thinking** block, which is relabeled **Thought process** when the response completes. After the response completes, its tool calls and reasoning collapse together into a single **View work** group, and the final answer stays visible. Expand **View work** to inspect them.

### Fine-tuning

Select **Models > Fine-tuning** to open the fine-tuned models list, start a fine-tuning job against an eligible base model, and track job progress. Enabled by default; see [NeMo Studio Fine-tuning](/documentation/studio/customization).

### Workspaces

Keep models and data organized in dedicated workspaces.

### Datasets

Select **Resources > Datasets** to open the Datasets list. It shows only filesets whose purpose is **Dataset**. **Workspace > Filesets** shows every fileset in the workspace, whatever its purpose.

- **Create a dataset** — Select **Create Dataset**. The new fileset gets the Dataset purpose.
- **Open a dataset** — Select a row, or choose **View** from its row actions. The detail page has two tabs: **Dataset Card**, which opens by default, and **Files**. Each tab has its own URL (`/workspaces/<workspace>/datasets/<name>/card` and `.../files`), so you can bookmark or share a tab directly. If you open a non-dataset fileset under a Datasets URL, Studio redirects you to the same page under **Filesets**.
- **Edit or delete** — Use **Edit** or **Delete** from the row actions.

### Filesets

Select **Workspace > Filesets** to list every fileset in the workspace. Fileset detail pages use the same two tabs as datasets. The **Card** tab is labeled **Dataset Card** or **Model Card** depending on purpose. A dataset opens on its card. Other filesets open on **Card** when the fileset has a root README, and on **Files** otherwise.

#### Copy a fileset to a new local fileset

Some filesets are backed by external storage and are read-only, such as one registered from Hugging Face, NGC, or GitHub. To get an editable copy, choose **Copy to New Fileset** from the row actions in the **Datasets** or **Filesets** list:

1. Enter a **Name** for the copy. It defaults to a copy name based on the source, and must be unique in the workspace. Optionally edit the **Description**.
2. Select **Copy**. Studio creates a local-storage fileset in the same workspace with the source's purpose and metadata, then copies every file into it. The dialog shows progress as **Copied N of M files**.

The source fileset isn't changed. Files pass through your browser, so a large fileset can take a while to copy. Keep the page open until the copy finishes. If a file fails to copy, Studio deletes the partial fileset. If you close or reload the page during the copy, that cleanup doesn't run and a partial fileset can remain; delete it manually.

#### Fileset purposes

Filesets organize files by **purpose**, which determines which metadata fields are available. Purpose is chosen at creation time and can't be changed afterward.

| Purpose     | Use for                                                                                                                                                                                                                |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Generic     | Files that don't fit the Dataset, Model, or Environment categories. Doesn't add purpose-specific metadata fields.                                                                                                      |
| Dataset     | Default for new filesets. Training and evaluation data. Enables dataset-specific metadata, including schema information. Use built-in tools to transform data schemas with LLM assistance or create train/test splits. |
| Model       | Model weights and checkpoints. Enables model-specific metadata, including tool-calling and model configuration fields.                                                                                                 |
| Environment | Executable environment packages consumed by sandboxed workloads.                                                                                                                                                       |

#### File formats

Format support depends on what you're doing with the file:

| Surface                       | What's supported                                                                                                                                                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Upload and storage (Files)    | Any file type. The Files service stores files without checking their format.                                                                                                                                                         |
| Studio file preview           | JSON and JSONL as formatted code, Markdown as rendered text, CSV as a table, images as images, and other text files as plain text. Binary files other than images, such as Parquet or PDF, have no preview; download them instead. |
| Studio dataset schemas        | JSON (`.json`), JSONL (`.jsonl`), CSV (`.csv`), and Parquet (`.parquet`) files in a dataset. Other files, such as READMEs, licenses, and images, are skipped.                                                                       |
| Consuming services            | Each service accepts its own input formats. See the table below and each service's documentation.                                                                                                                                     |

A file you can upload might not be previewable, and a file you can preview might not be accepted by the service you want to use it with. Input formats for services that read filesets:

| Service                                               | Supported File Types                  |
| ----------------------------------------------------- | ------------------------------------- |
| [Data Designer](/documentation/design-synthetic-data) | `.json`, `.jsonl`, `.csv`, `.parquet` |

### Anonymizer

Use **Data Preparation > Anonymizer** to detect and protect PII in a dataset, choosing a substitute, redact, annotate, hash, or rewrite strategy, previewing the result on a few records, and running a full job. Enabled by default.

For the full workflow, see [NeMo Studio Anonymizer](/documentation/studio/anonymizer).

### Safe Synthesizer

Use **Data Preparation > Safe Synthesizer** to create and monitor privacy-preserving synthetic tabular data jobs from NeMo Studio. The Studio page provides access to job creation, job status, details, reports, and result downloads for Safe Synthesizer workflows.

For the full workflow, see [Synthesize Safe Data](/documentation/synthesize-safe-data).

### Evaluations

Studio provides separate agent, model, and workspace evaluation views:

| Location                                   | What it shows                                                                                                                                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Agents > select an agent > Evaluations** | In-progress and completed evaluations in one table, and experiments scoped to the selected agent. Start a new run with **Run Evaluation**.                                                        |
| **Models > Model Evaluations**             | The Model Evaluations page: start a model evaluation with **Run Evaluation**, and review job results and per-row scores. See [Studio Model Evaluations](/documentation/studio/model-evaluations). |
| **Agent Development > Experiments**        | Experiments and their evaluations across the workspace, evaluation drill-down, and side-by-side run comparison. See [Studio Experiments](/documentation/studio/experiments).                      |

Use the agent's **Evaluations** tab when reviewing how a specific agent performed. Use **Experiments** for the broader workspace history.

### Experiments

Use **Agent Development > Experiments** to run an evaluation against an agent from the UI — selecting the agent and judge model, uploading a dataset and evaluation config — and to compare results across runs on the experiment leaderboard.

For the full workflow, see [NeMo Studio Experiments](/documentation/studio/experiments). For concepts, the data model, and the CLI and SDK workflows, see [Experiments](/documentation/evaluate-models/experiments).

### Jobs

Track and manage all platform jobs from a single view. The Jobs page aggregates jobs across enabled capabilities, such as Data Designer, so you can monitor progress, view logs, download artifacts, and cancel jobs in one place.

Navigate to **Jobs** in the workspace sidebar to see all jobs in the current workspace.

**Search and filter** — Find jobs by name, filter by status, or narrow results by creation or update date range.

**Status tracking** — Each job displays its current status:

| Status     | Description                                |
| ---------- | ------------------------------------------ |
| Created    | Job has been created but not yet scheduled |
| Pending    | Job is queued and waiting for resources    |
| Active     | Job is currently running                   |
| Completed  | Job finished successfully                  |
| Error      | Job encountered an error                   |
| Cancelled  | Job was cancelled by a user                |
| Cancelling | Cancellation is in progress                |
| Paused     | Job execution is paused                    |
| Pausing    | Job is transitioning to paused             |
| Resuming   | Paused job is restarting                   |

**Service routing** — Clicking a job navigates to its service-specific detail view when one exists. Jobs from services that aren't enabled fall back to the generic job detail view.

**Cancelling a job** — Active or pending jobs can be cancelled from the job list or the detail page. Cancelling a job permanently stops it and cannot be undone.

### Secrets

Store API keys and credentials to securely connect with external providers. Open **Settings** in the **Workspace** section and select **Manage Secrets**. See [manage-secrets](/documentation/get-started/core-concepts/manage-secrets) for details.
