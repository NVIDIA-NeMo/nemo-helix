## Highest Priorities

### Platform

1. Jobs show a `queued` status while waiting for executor concurrency capacity, and `max_active_jobs` limits admission (CLI)
2. Deleting a workspace asks for confirmation; `--yes` skips the prompt and non-interactive shells must pass it (CLI)
3. Inference Gateway middleware can refuse calls before serving, and gateway auth accepts `x-api-key` (Deployment)
4. Studio asks for confirmation before cancelling Data Designer and Anonymizer jobs (Studio)

### Agents

1. Execute extensions are renamed to post-run actions; `nemo agents post-run-actions list` replaces the old surface; please regression test (CLI)
2. Register agents with references and labels, then filter by label (CLI)
   1. Deployments stage files from `reference.fileset` and use `reference.container_image` (CLI)
3. Subprocess deployments are off on the `kubernetes` runtime unless `agents.subprocess_enabled: true` (CLI)
4. Tavily web search: agents and `nemo tavily search`/`extract` work when a workspace has a Tavily key, and the proxy can be disabled (CLI)

### Evaluation

1. Create a Harbor taskset, build its images, submit a run with `--taskset`, watch progress, then cancel (CLI)
2. Closed-book evaluation: a no-network taskset run is refused unless the model route ends with `nemo-evals-closed-book`
3. No-network and allowlist Harbor tasks reach the platform only through `agent_channel`, and a run with no platform entry is refused
4. Agent install reuse: each environment is built once and each agent installed once per environment; results should be unchanged; please regression test
5. Evaluate agent candidates from traces and view a transcript with `nemo intake traces show` (CLI)

### Fine-tuning

1. Prepare Parquet, CSV, or JSONL data with `nemo customization dataset prepare` and train on it (CLI)
2. `--dry-run` and `--dry-run-full` report problems before training starts (CLI)
3. Jobs without a learning rate use the documented per-method defaults, and LoRA jobs reuse a LoRA-enabled base deployment; please regression test

### Other

1. RC chart naming replaces nightly timestamped builds in the Helm install guide; please regression test install from an RC chart

### 6. Post-run actions replace execute extensions

| Field | Value |
|---|---|
| Disposition | `Proposed` |
| Confidence | `High` |

| Surface | `CLI / API-SDK` |

| Release-note coverage | `Missing — no 0.10.0 release note` |

**Description**

The breaking change in #3467 renames execute-job extensions to post-run actions without aliases. `extension` becomes `post_run_action`, and the default `noop` kind becomes `agents.noop`. A post-run action runs after a successful agent invocation inside the execute step. If it raises an error, the job fails. Agent entities can declare how they run and which post-run action kinds their jobs may use. Execute jobs also receive a run context, and skills for stored agents are staged before the job runs.

**User impact**

Plugin authors and job integrations that used `extension` or the `nemo.agents.execute_extensions` entry-point group must migrate.

#### CLI validation

```sh
nemo agents post-run-actions list
nemo agents execute --agent <AGENT> --post-run-action.kind <KIND>
```

Expected:

- `post-run-actions list` shows the installed actions, including `agents.noop`.
- An execute job with an allowed kind saves the action's results next to `fabric_run_result`. A kind the agent entity does not allow is rejected.
- An action that raises an error fails the job, and `fabric_run_result` is still available.

#### Additional validation

- Upgrade: a job request that still uses `extension` is rejected; confirm the error message: Needs clarification.
- Confirm Compass analysis runs still save `analysis-report` results through their post-run action; please regression test.
